Root Cause
redux-persist@6.0.0's redux-persist/lib/storage has a CJS/ESM interop issue with Vite.

The problem chain:

Vite resolves import storage from "redux-persist/lib/storage" using the package's module field → es/storage/index.js

That module calls createWebStorage('local') at module evaluation time

Due to Vite's ESM/CJS interop layer, the default export can get double-wrapped as { default: { getItem, setItem, removeItem } } instead of { getItem, setItem, removeItem }

When persistReducer later calls storage.getItem(key), it's calling on the wrapper object, not the actual storage adapter → storage.getItem is not a function

This is a known issue with redux-persist@6.0.0 + Vite + ESM projects.
